已做外科恢复、给求解轮询加 CPU 存活探针、给 guard 加逐实例自动恢复。

## 2. 僵死的精确签名（判据靠这个，别再靠日志年龄）

僵死实例的**全部**表现：

| 观测量 | 僵死时 | 健康时 | 是否会骗人 |
|---|---|---|---|
| AEDT 进程存在 | **存在** | 存在 | ✅ 会骗人 |
| `Responding` | **True** | True | ✅ 会骗人 |
| 工作集 | **13~846 MB**（从 3.7 GB 缩掉） | 3.6~5.7 GB | 较可靠 |
| **平均** CPU 利用率 | **15~21 核** | 8~20 核 | ⚠️ **最会骗人**（它是"曾经很忙"） |
| **实时** CPU 增量（60 s） | **0.1~0.2 核** | 1~56 核 | ✅ **唯一可靠** |
| 日志年龄 | 持续增长 | < 25 min | ⚠️ 启动补偿期也会老 |
| gRPC | 全断（`poll err`）或**静默阻塞** | 正常 | ⚠️ 阻塞时连异常都没有 |

**踩过的坑**：本次靠"平均利用率 + 进程存在"**三次误判**了健康实例。
**判定僵死只看实时 CPU 增量**（见第 4 节探针）。

## 3. 根因（两条，缺一不可）

1. **pyaedt 的 gRPC 调用会永久阻塞**。僵死时 `is_solved` **一次异常都不抛**，
   所以"连续异常计数"这类判据根本触发不了。worker 既不出点也不退出。
2. **`run_stage()` 看门狗只包住 `Analyze` 那一次调用**，包不住其后的轮询循环；
   而 `solve_and_extract` 轮询里的 `err_streak` 会在"提取验证"兜底失败时被清零
   （原 `batch_sweep_lc.py` 第 546 行），会话死了也永远退不出循环。

另外，**guard 恢复判据的盲区**是事故放大的主因：

- `dead` = worker 数不足；`all_stalled` = **全部**实例失速；`mem_bloat` = 提交 ≥88% 且 ≥5 个失速
- 8 实例里僵死 5 个时，**三个判据全不成立** → 白等数小时；
  而 8 个全僵死时 → **整批强杀重启**，每实例重做几何 7~10 min。
  即"要么不动，要么全灭"。

## 4. 已落地的改动

### 4.1 `C:\wpt\batch_sweep_lc.py`（求解轮询：CPU 存活探针）

备份：`_work\backup_pollfix_20260923_184504\batch_sweep_lc.py`

- 新增 `_aedt_cpu_seconds(pid)` / `_aedt_pid_of(d)`：用 kernel32 `GetProcessTimes`
  直接读 AEDT 进程累计 CPU 时间。**不依赖 pyaedt、不依赖 gRPC、不依赖 .profile 落盘**。
  - ⚠️ `GetProcessTimes` 的 4 个出参**必须传真实 FILETIME 结构地址**，传 NULL 会
    `access violation`（本次实测踩过）。
- 轮询循环（`solve_and_extract`）新增：
  - `CPU_STALL_SECS = 360`：连续 6 min CPU 时间零增长 → 判会话已死 → `kill_aedt()` + 放弃本点
  - 进程消失（`_aedt_cpu_seconds` 返回 None）→ 立即放弃本点
  - `session_err >= 12`（连续 gRPC 抛错）→ 放弃本点（保留原有语义）
  - 轮询上限 `range(90)` → `range(180)`：**BASE 单点实测可达 41 min**，原 30 min 会误判
- 放弃本点后交给 worker 既有的「同会话 BASE 回退 / 重开会话重试」路径，不改契约。

### 4.2 `_work\b1\b1_guard.py`（逐实例外科恢复 + 实时探针）

备份：`_work\backup_guardfix_20260923_190106\b1_guard.py`

- `--relaunch-stalled`（**已在计划任务里启用**）：失速 ≥3 个且单个 >150 min 时，
  逐实例 `relaunch_one()` 外科恢复（只杀各自 worker+AEDT），并**抑制整批重启**。
  - `relaunch_one()` 从 `.aedt.lock` 读权威 PID，**先杀 AEDT 再杀父 worker**，
    且校验父进程确为 `contract_worker`（防止 PID 复用误杀）。
- `aedt_pid_by_instance()` / `aedt_cpu_map()` / `_proc_cpu_seconds()`：
  每轮巡检做两趟 CPU 采样（间隔 12 s），把
  **「增量 <1 核 且 日志 >20 min 未更新」**的实例直接标为僵死并计入失速
  （`CPU_IDLE_LOG_MIN`），无需再等满 90 min 的落盘阈值。
  - ⚠️ `ROOT`/`B` 是 `main()` 的**局部**变量，探针必须显式传入（本次踩过 NameError）。

### 4.3 计划任务

```
b1_batch_guard  →  python b1_guard.py --root ...\b1 --restart --relaunch-stalled   (每 30 min)
```
