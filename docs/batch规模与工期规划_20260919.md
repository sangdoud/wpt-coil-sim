# 批量规模与工期规划（基于 batch1 实测速率）

日期：2026-09-19
数据来源：**batch1 实跑**（256 工况，8 实例并行，修正几何 ring 口径，固定盒 X±420）
适用：后续任何规模的同口径采集（300 / 1000 / 2560 / 5000 组）

---

## 1. 实测速率（不是文档预估值）

| 项 | 实测 | 样本 |
|---|---|---|
| 单点求解（OPT：柔性网格 + ⑥ + pref10 + rres1e-5） | **7.10 min**（中位 7.02，p10 6.08，p90 8.48） | n=24 点 |
| 单点求解（BASE 回退，紧几何） | **~20 min**（按文档 2.85× 比例外推，本批尚未出 BASE 点） | 待实测 |
| 单工况几何重建 + 摆位 | **7~10 min**（8 实例并发下；单实例 ~2 min） | 8 实例 × 首轮 |
| 点数 / 工况 | **21**（半扫）+ 镜像展开成 41 点曲线 | 契约 |
| BASE 回退占比 | **35 / 256 = 13.7%** | 本批闸门分布 |
| 实例上限 | **8**（内存硬约束：可用内存降到文档记录的 4.48 GB 下限） | 实测 |

> ⚠ 文档里的 4.78 min/点是**单实例、旧几何、旧空气域**下的数；本批实测 7.10 min
> （+49%），来源：几何更重（独立双面铁氧体）、空气域更大（±420 vs ±205/±330）、并发争用。

## 2. 成本模型

```
单工况（OPT） = 21 × 7.10 + 9  ≈ 158 min
单工况（BASE）= 21 × 20   + 9  ≈ 429 min
平均单工况   = 0.863×158 + 0.137×429 ≈ 195 min

墙钟（8 实例）= N × 195 min ÷ 60 ÷ 8 ≈ N × 0.4067 小时
```

| 组数 | 机时 | 8 实例墙钟 |
|---|---|---|
| 256（本批） | 833 h | **4.2 天** |
| 300 | 976 h | 5.1 天 |
| 1000 | 3,253 h | **17 天** |
| 2560 | 8,328 h | 43 天 |
| **5000** | **16,256 h** | **≈ 85 天（2.8 个月）** |

敏感性：

- 若全部走 OPT（无 BASE 回退）：5000 组 → **69 天**
- 若 BASE 占比升到 25%：5000 组 → 95 天
- 单点速率每差 1 min：5000 组的工期差 **≈ 12 天**

## 3. 压缩手段（按收益排序）

| # | 手段 | 5000 组效果 | 代价 / 限制 |
|---|---|---|---|
| ① | **硬件翻倍**：内存加到 64 GB 跑 16 实例，或加一台同配置机器 | **85 → 42 天** | 当前 8 实例已撞内存墙（可用 4.5 GB），瓶颈是内存不是 CPU；最干净的杠杆 |
| ② | **治 BASE 回退**（紧几何下柔性网格失效） | 85 → **69 天**（省 16 天） | 13.7% 的工况吃掉 30% 机时；需要专项解决 TAU Flex 在净间隙 <1.5 mm 时的表面网格损坏 |
| ③ | **收窄扫描跨度**（需软件端改契约） | 85 → **54 天** | 契约跨度 ±Lc(1+g/2) 远大于发射阵列实际宽度 ±(Lc+\|tg\|)/2，尾部近零耦合区约占 40% 的点；改动会改 M_sum_var 语义 |
| ④ | 点数 21 → 11 | 85 → 46 天 | **不建议**：文档离线实测 M_sum_var 最坏偏 14.8% ✗ |
| ⑤ | 网格/求解再提速 | ≤5~10% | ③放宽收敛、全局粗化、MeshLink、GPU 均已被文档实测否决 |
| ⑥ | 4 弦模板 | ±0 | 面数 −68% 但不带来耗时收益（文档实测） |

**推荐组合**：① + 分批交付 → 16 实例下 **1000 组 ≈ 8~9 天**，全量 ≈ 6 周，且第 9 天就能出第一批训练数据。

## 4. 存储模型（5000 组）

| 项 | 规模 | 说明 |
|---|---|---|
| AEDT 求解数据 `*.aedtresults` | **≤ 1.5 GB** | 每实例只保留当前解（~150 MB，被逐次覆盖）；已接入**逐点清理**，两点之间降到 ~5 MB |
| Windows 页面文件 | 一次性 ~17 GB | 8 实例内存压力下系统自动扩到 17.4 GB（实际只用 0.78 GB），压力解除后回收 |
| 逐点原始结果 `*_raw_runK.csv` | **~13 MB** | 21 × 5000 行 × ~120 B |
| 契约 CSV（4 个） | **~19 MB** | 41 × 5000 行 × ~90 B |
| 工程副本 | 8 × 12.1 MB ≈ 97 MB | 建副本时清 `.aedtresults` |

**结论：磁盘不是约束**（5000 组全程 < 2 GB 数据 + 一次性页面文件），无需扩容。

## 5. 大规模采集的工程建议

1. **抽样改 Sobol**：LHS 不可前缀扩展，分批交付时第二批无法与第一批构成同序列前缀，
   会破坏代理模型的增量训练（文档第 12.3 节也提过）。
2. **分批交付 + 验收点前置**：每批前 16 个工况覆盖 7 维极值与最紧间隙（含 BASE 回退），
   先出验收报告再铺全量——本批已按此执行，工作流可直接复用。
3. **断点续跑 + 看门狗**（本批已就位）：任何中断都不丢已算点位；重启即续算。
   注意：重启后该实例要重做一次几何（7~10 min），因此**不要频繁重启**。
4. **口径冻结**：几何（含拐角修正 ring）、空气域（X±420）、网格开关必须逐批一致，
   否则跨批数据不可比。详见《batch1 交付口径说明》。
5. **监盘指标**：单点耗时 p90、结果目录体积、可用内存、每实例点位增量。
   若单点 p90 突然抬升，先查内存/页面文件与是否有实例在重做几何。

```
4. python contract_launch.py 8 --batch <b> --root <dir> --boxx 420 --merge
5. python b1_status.py / b1_accept.py        # 巡检与验收
```
