## 1. 你要的改动

三个线圈（Tx1 / Tx2 / Rx）的**平面内线宽 3mm → 2mm**，线厚 0.5mm 不变。

改的是这个：

| 项目 | 改前 | 改后 |
|---|---|---|
| `XSectionWidth`（平面内线宽） | **3mm** | **2mm** |
| `XSectionTopWidth` | 3mm | 2mm |
| `XSectionHeight`（Z 向线厚） | 0.5mm | **0.5mm 不动** |
| `XSectionType / Orient / BendType` | Rectangle / Auto / Corner | 同前，不动 |
| 线圈路径（768 点 / 767 段） | — | **逐点原样复用，不动** |
| 匝数 / 匝间距 | 12 匝 / 4.5mm | 不动 |
| 引线（半径 0.3mm 圆柱） | — | **不动**（见第 7 节） |
| 铁氧体 / Region / 气隙 | — | **不动** |

线圈实体是「带矩形截面的 Polyline 扫掠」。路径 768 个点、767 段**全部是直线**
（没有圆弧/样条），路径长 **5131.9170 mm**，三个线圈完全相同 —— 这是能精确重建的前提。

## 2. 做法：不重建路径，只换截面

原对象是 `Polyline(3mm×0.5mm) ∪ 引线`，已经 Unite 成一个实体，截面参数改了也不会生效。
所以按下面四步做（脚本 `_probe\rebuild_width_pipeline.py`）：

| 步 | 动作 |
|---|---|
| 1 | 记录该线圈现有端子的**端面 ID / 中心 / 面积 / 极性** |
| 2 | 用一个覆盖全 XY 的大盒子，把旧铜带所在的 z 层切掉（Tx1 `z∈[-1.00,+0.25]`、Tx2 `z∈[-0.25,+1.00]`、Rx `z∈[0,30.25]`）—— 切完对象里**只剩引线** |
| 3 | 用从 `.aedt` 文本逐点提取的原路径（按「引线轴 x − 路径端点 x」反解出的偏移整体平移），以 `Rectangle 2mm × 0.5mm / Auto / Corner` 重建铜带 |
| 4 | `Unite`（端子会被摧毁）→ 在新对象上按原端面中心（±0.05mm）+ 面积匹配找回端面 → 用**原来的极性**重建 6 个端子 → `add_winding_coils` 挂回 Winding_Tx1 / Tx2 / Rx |

关键点：**引线一点没动**（只被切掉一段 0.25mm 的短桩，见下），路径也一点没动，
所以"只改了线宽"这件事是可验证的，而不是靠信任。

## 3. 自检：三层证据

### 3.1 截面朝向断言（防止把线宽改到 Z 向）

矩形 2×0.5 无论怎么摆，**横截面积都一样、体积都一样** —— 所以只看体积无法判断
改的是线宽还是线厚。脚本额外卡了「新铜带 z 跨度必须 = 0.5000mm」：

```
[Tx1] 新铜带 体积=7697.8395  z 跨度=0.5000 (应 0.5000)
```
三个线圈全部通过。**线上宽 2mm、Z 向厚 0.5mm 是被断言过的**，不是推断的。

### 3.2 3mm 回归：同一条代码路径重建回 3mm，看能不能还原原模型

| 量 | 原模型 | 重建 3mm | 差 |
|---|---|---|---|
| Tx1 铜带体积 | （推导 7697.89） | 7697.8395 | −36 ppm vs 解析值 7697.8755 |
| Tx2 铜带体积 | 同上 | 7697.8395 | 同上 |
| Rx 铜带体积 | 同上 | 7697.8395 | 同上 |
| Tx1 总体积 | 7750.7989 | 7750.5201 | −0.279（−36 ppm） |
| Tx2 总体积 | 7750.9649 | 7750.6858 | −0.279（−36 ppm） |
| Rx 总体积 | 7723.2137 | 7723.1450 | −0.069（−9 ppm） |
| Tx1/Tx2 面数 | 1550 | **1548** | −2 |
| Rx 面数 | 1544 | **1544** | 0 |
| 端子面 ID | 79351/79369/79387/79405/27705/27714 | **完全相同** | 0 |

面数变化正好说明了重建在做什么：切掉铜带时，Tx 引线在铜带外面还留了 **0.25mm 短桩**，
切掉它就少一个柱面 + 一个端面 = 2 面（Tx1/Tx2 各 −2）；Rx 的引线从铜带顶面才开始，
本来没有短桩，所以面数**一个不差**。体积那 −36 ppm 是 ACIS 布尔核的固有残差
（原模型自身 Tx1 与 Tx2 镜像就差 0.166 mm³ = 21 ppm）。

### 3.3 3mm ↔ 2mm 差值：必须精确等于铜带体积差

这是最硬的一条 —— 不依赖原模型，纯粹看同一代码路径两次重建的差：

| 线圈 | 3mm 体积 | 2mm 体积 | 差值 | 理论值 (路径长×1mm×0.5mm) | 误差 |
|---|---|---|---|---|---|
| Tx1 | 7750.5201 | 5184.5519 | 2565.9682 | 2565.9585 | **+0.0097（0.0004%）** |
| Tx2 | 7750.6858 | 5184.7174 | 2565.9684 | 2565.9585 | +0.0099 |
| Rx | 7723.1450 | 5157.1769 | 2565.9681 | 2565.9585 | +0.0096 |

### 3.4 存盘后的文本核对（对 C:\wpt 上的正式文件做的）

历史里现在留着 4 轮重建的折线（`TR_Tx1` 3mm、`TR_Tx1_1` 2mm、`TR_Tx1_2` 3mm、`TR_Tx1_3` 2mm），
所以不能只看"文件里有没有 2mm"——要**解析每个线圈最后一次 Unite 引用的工具件**：


`TR_*_3` 是最后创建的那一代（文件偏移最大），截面 2mm —— 这次改的确实是它。

### 对照解的可信度（这一步很重要）

3mm 对照解 19.968/19.567/24.100/3.400/0.15500 与历史基线
19.956/19.563/24.046/3.408/0.15558 **全部落在 0.3% 噪声底内**（最大偏差 k13 0.37%）
→ 说明「切铜带 → 重建 → 重新挂端子」这条流水线是**保真**的，
所以 2mm 那一列可以直接和基线对话，**L11 +1.68% / L33 +2.10% / k13 −2.50% 是真实效应**，
远超噪声底。

### 方向对不对？对，而且能解释

线宽 3→2mm、**匝间距固定 4.5mm** → 匝间净间隙从 1.5mm 变成 2.5mm
→ 相邻匝之间的反向互感减弱 → **自感升高**（L11 +1.7%、L22 +1.7%、L33 +2.1%）。
互感 M13 略降、而 L11/L33 同时涨，所以 **k13 降 2.5%**。
都符合预期，没有反号的怪现象。

### 耗时观察（单样本，仅供参考）

| 模型 | 单点求解 |
|---|---|
| 3mm 对照 | 9.8 分钟 |
| **2mm** | **12.6 分钟（+29%）** |

铜带更细 → 网格更难收敛，比之前「铁氧体越薄越慢」是同一现象。
只有各一个样本，**不能当成定论**，但整批估时建议按 +20~30% 留余量。

## 6. 批次脚本改了什么

只改了一行（`C:\wpt\batch_sweep_unit30.py` 第 51 行）：

```python
COIL_SIZE = 167.90   # 原 168.90
```

**为什么必须改**：`set_tx_gap()` 用 `tx1_center = -tg/2 - COIL_SIZE/2` 定位线圈。
`COIL_SIZE` 原本 = 线圈 X 向外尺寸 168.88（实测）。线宽变窄后外尺寸变成 **167.9018**，
如果还用 168.9，`tg` 就不再等于"两个发射线圈之间的间隙"，而是**比它大 1.0mm**，
整个 tg 维度的物理含义就漂了。改成实测值后 `tg` 语义完全不变。
（`COIL_SIZE` 同时决定铁氧体覆盖范围 `emit_lo/emit_hi`，改完也自动跟着线圈实际边缘走。）

其余逻辑**不用改** —— 批次脚本从来不碰线圈几何，只做移动和重建铁氧体。
