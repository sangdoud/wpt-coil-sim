# AEDT 2025 可行性自检 —— 使用说明

在装有 **2025 版 Maxwell** 的电脑上，一次性验证本 WPT 参数化方案能否运行。
**30 分钟内出结论**，不用等跑完整批才知道行不行。

---

## 一、需要的文件（放同一个文件夹）

| 文件 | 从哪来 |
|---|---|
| `preflight_2025.py` | 本脚本 |
| `batch_sweep_unit30.py` | 几何辅助函数（同目录） |
| `Projecttonight.aedt` | 你的 GitHub 仓库 `sangdoud/wpt-coil-sim` 根目录（25,155,997 字节，md5 `9bb98917…`；**务必是这一版，旧版 24,782,600 字节的会导致结果对不上**） |

> 三个文件必须**在同一个文件夹**里。脚本默认找同目录下的 `Projecttonight.aedt`。

## 二、装依赖

```bash
pip install pyaedt==1.3.0
```

AEDT 侧无需额外配置，pyaedt 会自动探测已安装的版本。

## 三、运行

```bash
python preflight_2025.py
```

全程约 **25–30 分钟**（2 个点求解 + 非图形模式测试）。结果实时打印，同时写入 `preflight_report.txt`。

## 四、如果朋友的 2025 不是 2025.1

改脚本开头这一行即可（例：2025.2 就写 `"2025.2"`）：

```python
TARGET_VERSION = "2025.1"
```

找不到该版本时脚本会**自动回退**到检测到的最高可用版，并在报告里注明。

## 五、怎么看结果

末尾出现 **`PASS=... HANG=0 FAIL=0`** 即代表可用。

| 标记 | 含义 | 怎么办 |
|---|---|---|
| `[PASS]` | 该阶段正常 | — |
| `[HANG]` | **超过 360 秒无响应，已强杀 AEDT** | 多半是**非图形模式**不兼容。服务器上必须保留 GUI(RDP) 会话 |
| `[FAIL]` | 明确报错，报告里带原因 | 按提示查：license / 版本配对 / 工程文件 / 提取接口 |

### 自检覆盖的 6 个关键点
1. pyaedt 是否安装、版本是否与 AEDT 配对
2. AEDT 版本条目**目录是否真实存在**（防止指到已卸载的残留路径）
3. GUI 会话能否启动并打开 `WPT_G` 工程、求解类型是否 Magnetostatic
4. **几何重建**（铁氧体 delete/rebuild）是否正常
5. **单点求解 + 提取**，并与本机 2024.1 的已知参考值**对比漂移**（超 2% 会报出来）
6. **non_graphical 无界面模式**下的几何重建是否正常 ← 服务器部署的关键风险点

## 六、三个必须知道的坑

1. **绝不修改 `SAVE_PROJECT = False`**。新版保存会把 `.aedt` **单向升级**成 2025 格式，之后 2024.1 再也打不开。脚本全程不保存工程。
2. **结果可能微漂移**。不同版本的网格/求解器默认值有差异，L/M 差零点几个百分点属正常。这些数据**不要和 2024.1 的 1705 点混进同一个训练集**。
3. **长跑仍需重启设计**。会话退化问题与版本无关，批量脚本里"每 N 点重启会话 + 快速失败检测"要保留。

## 七、自检通过后

把批量脚本里的版本号改掉即可开跑：

```python
AEDT_VERSION = "2025.1"      # batch_sweep_unit30.py / fill_missing_unit30.py
```
